## 2026-09-05 — Implemented confirmed-lesson project-over-global precedence

Modified lexical retrieval ordering to rank project-scoped lessons above global lessons. The SQL `ORDER BY` now sorts by scope priority (project = 0, global = 1) first, then by BM25 score, then by lesson ID for deterministic tiebreaking. This means when both a project lesson and a global lesson match a query, the project lesson always appears first in results — even if the global lesson has a stronger BM25 score. Within each scope tier, BM25 ordering is preserved. The limit is applied after this ordering, so a `limit: 1` query returns the best project match when one exists. Added 5 behavior tests covering equal-relevance precedence, stronger-global-BM25 precedence, global-only ordering, within-project BM25 ordering, and limit interaction with precedence. Verification passed with 207 tests plus typecheck and build.

## 2026-09-05 — Implemented unresolved lesson conflict suppression during retrieval

Added `suppressConflictingLessons()` as a post-retrieval filter that removes lower-ranked lessons whose body text conflicts with higher-ranked lessons in the same result set. Conflict is detected via Jaccard similarity on extracted body terms, using the same `MINIMUM_OVERLAP_THRESHOLD` (0.15) as duplicate detection. Results are processed in rank order (project-scoped first per T45 precedence), so project lessons always win over conflicting global lessons. The function returns both kept and suppressed results with the conflicting lesson ID and overlap score for receipt/audit purposes. Supports a custom threshold override. ## 2026-09-06 — Integrated fail-open primary-system-block context injection with OpenCode

Implemented the context injection module in the OpenCode adapter (`src/opencode/context-injection.ts`). The module wires the existing retrieval → conflict-suppression → context-packing pipeline into OpenCode's hook lifecycle with four functions: `createInjectionState()` creates per-adapter mutable state; `prepareInjection()` resolves feature toggles and private mode, runs retrieval through an injected callback, suppresses conflicts, packs lessons into a system block, and stores pending injection keyed by session ID; `applyInjection()` merges the pending block into the primary system element (first entry in the `system[]` array) and clears the pending state; `clearPendingInjection()` provides explicit cleanup. The module is fail-open: private mode and disabled retrieval return early, retrieval errors are caught and returned as structured `failed` results, missing session IDs in the system-transform hook produce a no-op, and ambiguous same-session queuing (a second `prepareInjection` call before the first message's system transform fires) clears both pending injections rather than risking cross-message context contamination. The retrieval function is injected as a parameter to decouple from direct database access (the full adapter wiring is T71). Added types `PendingInjection`, `InjectionState`, `RetrieveLessonsFn`, `PrepareInjectionInput`, `PrepareInjectionResult`, and `ApplyInjectionResult`. Added 22 behavior tests covering private mode, disabled retrieval, empty/whitespace queries, no-match retrieval, successful preparation and application, ambiguous correlation suppression, retrieval failure (Error and non-Error), missing session ID, no pending state, system block merging (into existing block, empty array, multi-element array), pending state cleanup, concurrent session isolation, receipt accuracy, messageId handling, and full round-trip prepare→apply.
