## 2026-09-06 — Atomic privacy-first hard deletion (T12)

Added `hardDeleteAllStoredData` (src/core/hard-deletion.ts) and a CLI `hard-delete` command, completing the design's privacy-first deletion requirement. Row deletion runs as one atomic transaction across all fourteen tables in children-first order; FTS entries are removed by the existing delete triggers on `lesson_versions` and `document_chunks`. After commit, the WAL is checkpointed and truncated, the database is vacuumed to clear freelist residue, the WAL is truncated a second time (VACUUM itself writes through the WAL), all managed backups are purged, and a clean baseline backup is created. Once the delete transaction commits there is intentionally no rollback — a later failure (e.g. baseline creation) still leaves the data deleted, which is the point of a privacy-first delete; each stage reports through `HardDeletionError` with a `stage` field. The CLI prints the warning that all managed historical recovery points will be lost, discloses that user-copied exports and SSD/external backups are outside package control, and requires typing the exact confirmation phrase (`HARD_DELETE_CONFIRMATION_PHRASE`, kept in shared types so prompt and tests cannot drift) before proceeding; EOF or a wrong phrase aborts. Tests: 3 core tests (full deletion with per-table counts, empty FTS, zero freelist, truncated WAL, purged backups, integrity-checked empty baseline, and schema survival; rollback on transaction failure; closed-connection refusal) and 3 CLI tests (wrong-phrase abort, EOF abort, confirmed deletion). ## 2026-09-06 — Implemented decayed evidence aggregation with profile backoff and uncertainty (T20)

Added the evidence-aggregation module (src/core/evidence-aggregation.ts, types in src/types/evidence-aggregation-types.ts, constants in src/core/evidence-aggregation-constants.ts). `aggregateDecayedEvidence()` aggregates one exact provider/model/variant's evidence into per-dimension estimates (quality, reliability, cost, latency in fixed order), each carrying mean, Kish effective sample size, uncertainty (sqrt of weighted variance / ESS — for 0/1 quality and reliability values this equals the classic sqrt(p(1-p)/ESS) standard error), sample count, decayed weight, and the backoff level used.

## 2026-09-09 — Added the CLI outcome-failure reclassification command (T90)
