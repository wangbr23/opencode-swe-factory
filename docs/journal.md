## 2026-09-05 — Implemented confirmed-lesson project-over-global precedence

Modified lexical retrieval ordering to rank project-scoped lessons above global lessons. The SQL `ORDER BY` now sorts by scope priority (project = 0, global = 1) first, then by BM25 score, then by lesson ID for deterministic tiebreaking. This means when both a project lesson and a global lesson match a query, the project lesson always appears first in results — even if the global lesson has a stronger BM25 score. Within each scope tier, BM25 ordering is preserved. The limit is applied after this ordering, so a `limit: 1` query returns the best project match when one exists. Added 5 behavior tests covering equal-relevance precedence, stronger-global-BM25 precedence, global-only ordering, within-project BM25 ordering, and limit interaction with precedence. ## 2026-09-05 — Implemented unresolved lesson conflict suppression during retrieval

## 2026-09-06 — Mapped OpenCode requests and delegated subtasks into task boundaries

The module maps OpenCode `chat.message` events into task records with deterministic profiling and per-session tracking. `createTaskBoundaryState()` creates mutable per-adapter state tracking active tasks per session. `handleTaskBoundary()` determines the boundary type (top-level vs subtask) from the agent field — the first message's agent becomes the root agent; subsequent messages from the same (or undefined) agent create new top-level tasks (completing the previous), while messages from different agents create subtasks parented to the current top-level. The handler checks feature toggles (private mode, recording), profiles the task text via an injected `ProfileTaskFn`, creates the task record and persists the profile, and tracks the active task for later completion. `completeActiveTask()` and `completeSessionTasks()` mark individual or all session tasks as completed (for session-end cleanup). `getActiveTask()` returns the current active task for a session+agent for later outcome attachment. `extractMessageText()` extracts text content from OpenCode Part arrays. Root agent tracking uses an explicit `rootAgentEstablished` flag to distinguish "not yet set" from "set to undefined" (handles the case where the first message has no agent).
