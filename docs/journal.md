## 2026-09-06 — Atomic privacy-first hard deletion (T12)

Added `hardDeleteAllStoredData` (src/core/hard-deletion.ts) and a CLI `hard-delete` command, completing the design's privacy-first deletion requirement. Row deletion runs as one atomic transaction across all fourteen tables in children-first order; FTS entries are removed by the existing delete triggers on `lesson_versions` and `document_chunks`. After commit, the WAL is checkpointed and truncated, the database is vacuumed to clear freelist residue, the WAL is truncated a second time (VACUUM itself writes through the WAL), all managed backups are purged, and a clean baseline backup is created. Once the delete transaction commits there is intentionally no rollback — a later failure (e.g. baseline creation) still leaves the data deleted, which is the point of a privacy-first delete; each stage reports through `HardDeletionError` with a `stage` field. The CLI prints the warning that all managed historical recovery points will be lost, discloses that user-copied exports and SSD/external backups are outside package control, and requires typing the exact confirmation phrase (`HARD_DELETE_CONFIRMATION_PHRASE`, kept in shared types so prompt and tests cannot drift) before proceeding; EOF or a wrong phrase aborts. Tests: 3 core tests (full deletion with per-table counts, empty FTS, zero freelist, truncated WAL, purged backups, integrity-checked empty baseline, and schema survival; rollback on transaction failure; closed-connection refusal) and 3 CLI tests (wrong-phrase abort, EOF abort, confirmed deletion). Verification: 408 tests, typecheck, and build all pass. This unblocks T75 (hard-deletion acceptance scenarios).

## 2026-09-06 — Implemented decayed evidence aggregation with profile backoff and uncertainty (T20)

Added the evidence-aggregation module (src/core/evidence-aggregation.ts, types in src/types/evidence-aggregation-types.ts, constants in src/core/evidence-aggregation-constants.ts). `aggregateDecayedEvidence()` aggregates one exact provider/model/variant's evidence into per-dimension estimates (quality, reliability, cost, latency in fixed order), each carrying mean, Kish effective sample size, uncertainty (sqrt of weighted variance / ESS — for 0/1 quality and reliability values this equals the classic sqrt(p(1-p)/ESS) standard error), sample count, decayed weight, and the backoff level used.

Evidence selection rules, all enforced in one SQL pass: only execution-linked signals aggregate — task-level signals (e.g. explicit acceptance without a linked execution) cannot be attributed to a single model/variant without guessing, and the design forbids false outcome attribution; superseded signals are excluded so retracted acceptances cannot double-count; task profiles must carry the current `TASK_TAXONOMY_VERSION` so dimension matches stay comparable across taxonomy bumps.

Decay and backoff: item weight = signal confidence × exponential decay (30-day half-life by default; evidence older than 90 days is excluded outright). Profile matching backs off across a fixed ladder — exact activity/domain/complexity, then activity/domain, then domain, then any current-taxonomy profile — and each dimension independently uses the narrowest level that carries evidence, widening only when necessary. Targets with null activity/domain start at the first level whose required dimensions exist. Coarse-level evidence is labeled with its `backoffLevel`; per a new decision entry, the level weight is applied by downstream ranking (T61), not by aggregation, because a constant per-level weight cancels out of the weighted mean and Kish ESS — putting it in the item weights would fake precision without changing the estimates. Tests (12): empty store, decay arithmetic and ESS, max-age exclusion, all four backoff levels with widening evidence pools, null-dimension targets, exact model/variant attribution with other-model/variant and task-level signal exclusion, supersession exclusion, cost/latency separation, legacy-taxonomy exclusion, and input validation. Verification: 537 tests plus typecheck and build. This unblocks T61 (which applies backoff weights in utility scoring) and T24.
